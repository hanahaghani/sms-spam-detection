# دسته‌بندی پیام‌های اسپم (SMS Spam Classification)

این ریپازیتوری شامل دو رویکرد برای تشخیص و دسته‌بندی پیام‌های اسپم است:

### یادگیری ماشین (Machine Learning)

پیاده‌سازی با استفاده از **TF-IDF** برای استخراج ویژگی‌های متنی و مدل‌های کلاسیک یادگیری ماشین.

### یادگیری عمیق (Deep Learning)

پیاده‌سازی با استفاده از **PyTorch** و یک شبکه عصبی سفارشی برای دسته‌بندی پیام‌ها.


# SMS Spam Classification — Deep Learning

در این پروژه، تشخیص پیام‌های **Spam** و **Ham** را با استفاده از یک شبکه عصبی در **PyTorch** پیاده‌سازی کردیم.

هدف پروژه فقط ساخت یک مدل نبود؛ بلکه بررسی فرآیند آموزش شبکه عصبی، بهینه‌سازی، کنترل Overfitting و مقایسه چند تکنیک مختلف بود.

## Data Preprocessing

### Text Cleaning

ابتدا متن پیام‌ها پاک‌سازی و آماده‌سازی شد تا داده‌ها برای استخراج ویژگی مناسب باشند.

### TF-IDF

از **TF-IDF** برای تبدیل متن به ویژگی‌های عددی استفاده شد.

TF-IDF به مدل کمک می‌کند کلماتی را که برای تشخیص Spam مهم‌تر هستند وزن بیشتری بدهد و در عین حال تأثیر کلمات بسیار رایج را کاهش دهد.

در این پروژه، خروجی TF-IDF شامل **1056 ویژگی** بود و به عنوان ورودی شبکه عصبی استفاده شد.

## Model Architecture

معماری شبکه عصبی به صورت زیر است:

```text
1056 → 256 → 128 → 64 → 1
```

سه لایه Hidden برای یادگیری الگوهای پیچیده‌تر از ویژگی‌های متنی استفاده شدند و در نهایت یک خروجی برای مسئله Binary Classification داریم.

### ReLU

بعد از لایه‌های مخفی از **ReLU** استفاده شد.

ReLU یک Non-linear activation ایجاد می‌کند و به شبکه اجازه می‌دهد روابط پیچیده‌تر موجود در داده‌ها را یاد بگیرد.

### Dropout

از **Dropout** برای کاهش Overfitting استفاده شد.

در آزمایش‌های انجام‌شده، چند مقدار مختلف Dropout بررسی شد و مقدار **0.5** عملکرد مناسب‌تری نسبت به مقادیر آزمایش‌شده دیگر داشت.

## Loss Function

برای محاسبه خطای مدل از:

```text
BCEWithLogitsLoss
```

استفاده شد.

چون مسئله ما Binary Classification است و مدل یک خروجی تولید می‌کند، این Loss انتخاب مناسبی برای محاسبه خطای Spam/Ham است.

## Optimizer

برای به‌روزرسانی وزن‌های شبکه از **Adam** استفاده شد.

Adam به دلیل ترکیب سرعت همگرایی مناسب و سازگاری با نرخ یادگیری برای آموزش این شبکه انتخاب شد.

## Learning Rate

مقدار اولیه Learning Rate برابر با:

```text
0.001
```

در نظر گرفته شد.

این مقدار سرعت تغییر وزن‌های شبکه را کنترل می‌کند و باعث می‌شود مدل در هر مرحله بیش از حد بزرگ یا بیش از حد کوچک به سمت مقدار بهینه حرکت نکند.

## Weight Decay

از **Weight Decay** برای کنترل پیچیدگی مدل و کاهش Overfitting استفاده شد.

این روش مدل را به سمت وزن‌های کوچک‌تر هدایت می‌کند و می‌تواند به Generalization بهتر کمک کند.

## Learning Rate Scheduler

از **StepLR** استفاده شد تا Learning Rate در طول آموزش کاهش پیدا کند.

تنظیمات استفاده‌شده:

```text
step_size = 5
gamma = 0.5
```

یعنی بعد از هر 5 Epoch، نرخ یادگیری نصف می‌شود.

این کار کمک می‌کند مدل در ابتدای آموزش سریع‌تر یاد بگیرد و در مراحل بعد با قدم‌های کوچک‌تر به سمت نقطه بهینه حرکت کند.

## Early Stopping

برای جلوگیری از ادامه آموزش بعد از شروع Overfitting از **Early Stopping** استفاده شد.

اگر Validation Loss برای چند Epoch بهبود پیدا نکند، آموزش متوقف می‌شود.

در این پروژه مقدار:

```text
patience = 3
```

استفاده شد.

## Batch Training

داده‌ها با استفاده از **DataLoader** و Batch Size برابر با **32** وارد مدل شدند.

استفاده از Batch باعث می‌شود مدل داده‌ها را به صورت گروهی پردازش کند و آموزش نسبت به پردازش کل داده‌ها در هر مرحله مدیریت‌پذیرتر باشد.

در طول پروژه چند تکنیک و تنظیم مختلف بررسی شدند، از جمله:

هدف از این آزمایش‌ها بررسی تأثیر هر روش روی Training و Validation و انتخاب ترکیب مناسب‌تر برای این مسئله بود.

در نهایت، ترکیبی از **ReLU + Dropout + Adam + Weight Decay + StepLR + Early Stopping** به عنوان تنظیم نهایی پروژه انتخاب شد.

## Prediction

مدل در خروجی یک **Logit** تولید می‌کند.

برای تبدیل آن به احتمال Spam از Sigmoid استفاده شد:

```text
Logit → Sigmoid → Spam Probability
```

سپس با Threshold برابر با `0.5`، پیام به یکی از دو کلاس زیر اختصاص داده می‌شود:

```text
0 → Ham
1 → Spam
```
